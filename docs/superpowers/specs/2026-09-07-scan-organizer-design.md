## 1. 목적과 범위

### 1.1 하는 일

담당자가 스캔 폴더에서 PDF 여러 개를 선택하면, 각 PDF 첫 페이지에 적힌 결의번호를 읽어 그 번호로 **파일명을 바꾼다.** 바꾸기 전에 결과를 화면에 보여주고 사람이 승인한다.

### 1.2 하지 않는 일

| 제외 항목 | 이유 |
|---|---|
| 폴더 감시 (상시 실행) | 사용자가 필요할 때 직접 실행 |
| 파일 이동·폴더 분류 | 보관은 담당자가 직접 진행 |
| 파일 삭제 | 어떤 경우에도 없음 |
| OCR | 스캐너가 텍스트 레이어를 이미 생성함 |
| 부팅 자동 실행, Windows 알림 | 상시 실행이 아니므로 무의미 |
| 2페이지 보조 검색 | 1차 범위에서 제외 |
| 네트워크 통신 | 없음. 문서가 PC를 벗어나지 않음 |

### 1.3 제안서 대비 변경

원 제안서는 무인 폴더 감시형이었으나, 협의 결과 **사용자 선택 + 사전 확인형**으로 변경한다.

**유지되는 요구사항:** FR-03(첫 페이지만 추출), FR-04(정규식 추출), FR-05(정규식 설정화), FR-06(파일명 변경), FR-07(중복 방지), FR-10(삭제 금지), FR-11(처리 로그)

**삭제되는 요구사항:** FR-01, FR-02, FR-08, FR-09, FR-12, FR-13, FR-14, FR-15, FR-16, FR-17

**삭제되는 제안서 항목:** 4.3(폴더 정리 규칙), 5.3(시스템 구성도), 설정 항목 중 `watch_dir`·`dest_root`·`folder_rule`·`unsorted_dir`·`stable_seconds`·`max_wait_seconds`·`notify`

## 3. 결의번호 형식 (확정)

| 항목 | 내용 |
|---|---|
| 형태 | `YYYYMMDD-` + 일련번호 |
| 일련번호 자릿수 | **7자리 또는 4자리** (두 가지만 존재) |
| 예시 | `20260315-0000005`, `20260414-0001` |
| 문서상 표기 | 라벨(`결의번호 :`)이 붙는 경우와 단독으로 찍히는 경우가 **혼재** |
| 파일명에 쓸 부분 | 번호 전체 (`20260315-0000005`) |

### 3.1 추출 규칙

공백·줄바꿈을 하나의 공백으로 정규화한 뒤, 아래를 **순서대로** 시도한다.

```
1단계 (라벨 우선)  결의번호\s*[:：]?\s*(\d{8}-(?:\d{7}|\d{4}))(?!\d)
2단계 (단독)       (\d{8}-(?:\d{7}|\d{4}))(?!\d)
```

두 단계 모두 실패하면 **미인식**으로 처리한다.

**설계 근거:**

- **라벨을 먼저 시도하는 이유** — 첫 페이지에는 계좌번호·사업자번호·금액·전화번호 등 다른 숫자가 함께 찍힌다. 라벨이 있으면 그것이 가장 확실한 근거다.
- **7자리를 4자리보다 먼저 두는 이유** — 순서가 반대면 `0000005`에서 앞 4자리 `0000`만 매치되어 잘못된 번호가 만들어진다.
- **`(?!\d)` 뒤 경계** — 매치 직후에 숫자가 더 오면 실패시킨다. 더 긴 숫자열의 일부가 잘못 잡히는 것을 막는다.
- **자릿수를 `{4,7}` 범위로 두지 않는 이유** — 실제 형식이 7과 4 두 가지뿐이므로 정확히 고정하는 편이 오인식이 적다. 5·6자리는 인식되지 않아야 한다.

첫 매치를 사용한다.

## 4. 화면 흐름

```
[1] 프로그램 실행 (스캔정리_실행.bat 더블클릭)
[2] "파일 선택" 클릭 → 탐색기에서 PDF 여러 개 선택
[3] 선택된 파일을 파일 수정 시각 오름차순(= 스캔된 순서)으로 정렬
[4] 각 PDF의 첫 페이지만 읽어 결의번호 추출
[5] 목록 표시 — 사용자가 눈으로 확인
[6] "이름 변경 실행" 클릭
[7] 정상·중복 건만 제자리에서 이름 변경. 미인식 건은 손대지 않음
[8] 결과 요약 표시 + 정리기록.log 기록
```

### 4.1 목록 화면

| 수정시각 | 원본 | 인식된 번호 | 새 이름 | 상태 |
|---|---|---|---|---|
| 10:31 | `Scan_0007.pdf` | `20260315-0000012` | `20260315-0000012.pdf` | 정상 |
| 10:32 | `Scan_0008.pdf` | `20260315-0000005` | `20260315-0000005.pdf` | 정상 |
| 10:33 | `Scan_0009.pdf` | (없음) | — | 미인식 |
| 10:34 | `Scan_0010.pdf` | `20260315-0000005` | `20260315-0000005_2.pdf` | 중복 |

**정렬 순서는 표시 및 처리 순서에만 영향을 준다.** 파일명은 각 PDF 안에 적힌 결의번호에서 나오므로, 스캔 순서가 결의번호 순서와 달라도 결과는 정확하다.

미인식 행은 시각적으로 구분한다(색상 등).

### 4.2 확인 단계의 의미

바꾸기 전에 전체 결과를 보여주는 것이 이 설계의 핵심이다. 오인식이 보이면 실행하지 않고 `config.ini`의 정규식을 고친 뒤 다시 선택하면 된다. 무인 자동 처리 대비 오인식 위험이 실질적으로 제거된다.

## 5. 이름 변경 규칙

| 규칙 | 내용 |
|---|---|
| 대상 파일명 | `{결의번호}.pdf` |
| 금지문자 치환 | `\ / : * ? " < > \|` → `-` (결의번호 형식상 발생 가능성은 낮으나 방어적으로 적용) |
| 중복 처리 | 같은 이름이 이미 있으면 `_2`, `_3` … 부여. **덮어쓰기 금지** |
| 중복 검사 범위 | 대상 폴더의 기존 파일 + 이번 배치에서 이미 확정된 이름 |
| 이동 | 없음. 같은 폴더 안에서 이름만 변경 |
| 삭제 | 없음 |

구현은 `pathlib.Path.rename()` 사용. 같은 폴더 내 이름 변경이므로 원자적이다.

## 6. 예외 처리

| 상황 | 처리 |
|---|---|
| 결의번호 못 찾음 | 이름 변경하지 않음. 원본 유지. 로그에 **추출 텍스트 앞 200자** 기록 (정규식 수정 근거) |
| 첫 페이지에 텍스트 없음 | 미인식과 동일 처리. 사유 "텍스트 없음" |
| PDF 손상·읽기 실패 | 해당 파일만 미인식 처리. 오류 내용 로그. **나머지 파일 처리는 계속** |
| 파일이 다른 프로그램에 잠김 | 해당 건 실패 기록 후 다음 파일로 진행 |
| 대상 파일명이 이미 존재 | `_2`, `_3` 접미어 |
| 선택한 파일이 PDF가 아님 | 목록에서 제외 |

**개별 파일의 오류가 전체 처리를 중단시키지 않는다.** 각 파일 처리를 예외로 감싸고, 실패 시 그 파일만 실패로 표시한 뒤 계속한다.

## 7. 설정 파일

`config.ini` — 프로그램과 같은 폴더. UTF-8, 한글 주석 포함.

```ini
[결의번호]
# 1단계: 라벨이 붙은 경우 (우선 적용)
라벨패턴 = 결의번호\s*[:：]?\s*(\d{8}-(?:\d{7}|\d{4}))(?!\d)

# 2단계: 라벨 없이 단독으로 찍힌 경우
단독패턴 = (\d{8}-(?:\d{7}|\d{4}))(?!\d)
```

정규식이 잘못되어 컴파일에 실패하면 **오류 메시지를 보여주고 프로그램이 계속 동작 가능한 상태를 유지한다.** (설정 실수로 프로그램이 죽지 않는다)

`config.ini`가 없으면 위 기본값을 코드 내장값으로 사용한다.

파일 5개.

| 파일 | 역할 |
|---|---|

### 9.1 코드 경계

`scan_organizer.py` 내부는 세 층으로 나눈다. GUI와 로직을 섞지 않는다.

| 단위 | 입력 → 출력 | 의존 |
|---|---|---|
| `extract_number(text, patterns)` | 텍스트 → 결의번호 or `None` | 없음 (순수 함수) |
| `read_first_page(path)` | 파일 경로 → 첫 페이지 텍스트 | `pypdf` |
| `plan_renames(paths, patterns)` | 파일 목록 → 처리 계획 목록 | 위 두 개 |
| `apply_renames(plan)` | 처리 계획 → 실행 결과 | `pathlib` |
| GUI | 위 함수 호출 + 표시 | tkinter |

**`plan_renames`가 파일을 건드리지 않는 것이 중요하다.** 계획 수립과 실행이 분리되어 있어야 4.1의 사전 확인 화면이 성립한다.

## 11. 테스트

### 11.1 자동 테스트

`extract_number`는 순수 함수이므로 `assert` 기반으로 검증한다. 프레임워크 없이 `python test_scan_organizer.py`로 실행.

| # | 입력 | 기대 |
|---|---|---|
| 1 | `결의번호 : 20260315-0000005` | `20260315-0000005` |
| 2 | `20260414-0001` (라벨 없음) | `20260414-0001` |
| 3 | `결의번호\n:\n20260315-0000005` (줄바꿈) | `20260315-0000005` |
| 4 | `20260315-000005` (6자리) | `None` — 자릿수 경계 |
| 5 | `20260315-00000055` (8자리) | `None` — `(?!\d)` 경계 |
| 6 | 계좌번호 등 다른 숫자만 있는 텍스트 | `None` |
| 7 | 라벨 있는 번호 + 다른 숫자 혼재 | 라벨 쪽 번호 |
| 8 | 빈 문자열 | `None` |

GUI는 자동 테스트하지 않는다.

### 11.2 수동 검수 (Windows 실기)

| ID | 시나리오 | 기대 결과 |
|---|---|---|

## 12. 미확정 사항

**실제 스캔 PDF 샘플이 아직 없다.** 정규식은 담당자가 구술한 형식(`20260315-0000005`, `20260414-0001`)에 근거한다. 실제 스캐너의 OCR 텍스트 레이어가 어떻게 추출되는지는 샘플 확보 후 검증이 필요하며, 다음이 달라질 수 있다.

- 라벨 텍스트의 정확한 표기 (`결의번호` / `문서번호` / `지출결의번호`)
- 하이픈이 다른 문자로 추출될 가능성 (`‐`, `–`, 공백 등)
- 표 안에 있을 경우 셀 경계가 공백·줄바꿈으로 어떻게 나타나는지

**대응:** 미인식 건의 추출 텍스트 앞 200자를 로그에 남기므로(6장), 실제 문서로 한 번 돌려보면 정규식을 어떻게 고쳐야 할지 즉시 드러난다. 정규식은 `config.ini`에서 코드 수정 없이 바꿀 수 있다.
